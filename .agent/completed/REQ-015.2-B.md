## ARCHIV-HINWEIS

Dieser Task wurde NICHT über die Pipeline ausgeführt. Nachträglich
archiviertes Formatbeispiel — die Arbeit ist bereits vor Einführung der
Pipeline erledigt und real verifiziert (28/28 Tests inkl. 5 neuer
T1–T5b-Tests). Aus `.agent/queue/` entfernt, damit `npm run agent:next`
diesen Task nicht mehr auswählt.

## CONTEXT (historisch)

`getGgaCabinetSchrankaktePdfData()` rief `getGgaCabinetAuditHistory()`
unbedingt auf; deren Zugriffs-Guard schloss OPERATOR pauschal aus
(GGA-04.1-Erbe). Ein berechtigter OPERATOR konnte seine eigene
Betreiber-Schrankakte dadurch nie laden.

## ACCEPTANCE_CRITERIA

- [ ] Berechtigter OPERATOR kann die eigene Betreiber-Schrankakte laden.
- [ ] Fremder OPERATOR (IDOR) bleibt blockiert.
- [ ] Interne Rollen erhalten weiterhin die vollständige, ungefilterte
      Historie — unverändert.
- [ ] Die Betreiber-Sicht enthält keine internen, nicht freigegebenen
      Daten (Task-/Blocker-/Cabinet-Audit-Einträge, interne E-Mails).
- [ ] Ein OPERATOR kann sich durch `audience`-Manipulation keine interne
      Sicht erschleichen.

## KNOWN_ISSUES

- `internalCollaborationRoles` NICHT einfach um OPERATOR erweitern — das
  würde die interne Historie vollständig für externe Betreiber öffnen.

## DO_NOT

- Nicht einfach OPERATOR zu `internalCollaborationRoles` hinzufügen.
- Keine serverseitige Mandanten-/Cabinet-Zugriffsprüfung entfernen.
